کیبورد iOS و دکمه «ثبت اطلاعات واریز»

چرا با باز شدن کیبورد در آیفون دکمه‌ی پایین مودال جابه‌جا می‌شود و صفحه زیادی اسکرول می‌خورد، و چطور درستش کنیم.

۱. مشکل چیست؟

مودال «اطلاعات حساب» تمام‌صفحه است (height: 100dvh): سربرگ بالا، بدنه‌ی اسکرول‌خور وسط و دکمه‌ی «ثبت اطلاعات واریز» پایین. روی اندروید و دسکتاپ درست کار می‌کند، اما در آیفون وقتی کاربر روی «کد پیگیری» می‌زند و کیبورد باز می‌شود:

  • کل مودال به بالا هل داده می‌شود و دکمه زیر کیبورد می‌رود؛
  • صفحه بیش از حد اسکرول می‌خورد و بالا و پایین می‌پرد؛
  • کاربر برای زدن دکمه باید کیبورد را ببندد.

۲. چرا این اتفاق می‌افتد؟

  1. Safari با باز شدن کیبورد ارتفاع صفحه را کم نمی‌کند. اندروید صفحه را کوتاه می‌کند، ولی در iOS هم 100vh و هم 100dvh همان ارتفاع کامل می‌مانند و کیبورد فقط روی صفحه می‌نشیند. پس دکمه‌ی پایین مودال دقیقاً پشت کیبورد قرار می‌گیرد.
  2. Safari برای نشان دادن فیلد، کل صفحه را اسکرول می‌کند. فیلد فوکوس‌شده باید دیده شود، پس Safari کل صفحه را بالا می‌برد؛ مودال (که fixed است) هم با آن بالا می‌رود. این اسکرول اضافه همان «اسکرول زیاد» است.
  3. فقط یک چیز اندازه‌ی واقعی را می‌داند: window.visualViewport ارتفاع ناحیه‌ی قابل‌دیدن بالای کیبورد (height) و میزان اسکرول Safari (offsetTop) را می‌دهد. CSS به‌تنهایی در iOS به این عددها دسترسی ندارد.

۳. راهکار پیشنهادی: مودال را هم‌اندازه‌ی ناحیه‌ی دیدنی کنیم

به‌جای ثابت گذاشتن ارتفاع مودال روی 100dvh، ارتفاع و جای آن را با visualViewport هماهنگ می‌کنیم. چیدمان فعلی (سربرگ، بدنه‌ی اسکرول‌خور، دکمه) دست نمی‌خورد: وقتی مودال کوتاه شود، دکمه خودبه‌خود درست بالای کیبورد می‌نشیند و فقط بدنه اسکرول می‌خورد.

CSS (جایگزین ارتفاع فعلی .pay-modal):

.pay-modal { height: var(--vvh, 100dvh); transform: translateY(var(--vvt, 0px)); }
html:has(.pay-modal[open]) { overflow: hidden; } /* the page behind stays still */

JS (کنار بقیه‌ی کدهای مودال):

// iOS: keyboard doesn't shrink 100dvh — size the modal to the visible area instead
const vv = window.visualViewport;
const fit = () => {
  pm.style.setProperty("--vvh", vv.height + "px");    // visible height above the keyboard
  pm.style.setProperty("--vvt", vv.offsetTop + "px"); // undo Safari's page scroll
};
if (vv) { vv.addEventListener("resize", fit); vv.addEventListener("scroll", fit); }
pm.addEventListener("focusin", e => e.target.matches("input") &&
  setTimeout(() => e.target.scrollIntoView({ block: "center" }), 300)); // after the keyboard settles

نتیجه:

  • دکمه‌ی «ثبت اطلاعات واریز» همیشه دیده می‌شود و بالای کیبورد می‌ماند؛
  • پرش و اسکرول اضافه‌ی صفحه‌ی پشت مودال حذف می‌شود؛
  • با بسته شدن کیبورد، مودال خودش به تمام‌صفحه برمی‌گردد؛
  • روی اندروید و دسکتاپ هم بی‌خطر است (همان مقادیر فعلی را می‌دهد).

۴. دو بهبود کوچک کنارش

  1. دکمه‌ی Enter کیبورد کار ثبت را انجام دهد. روی فیلد کد پیگیری enterkeyhint="done" بگذاریم و با Enter همان دکمه‌ی ثبت زده شود. کاربر حتی لازم ندارد دنبال دکمه بگردد. 
    <input class="… track" inputmode="numeric" enterkeyhint="done">
code.onkeydown = e => e.key === "Enter" && pm.querySelector(".pay-save").click();
  2. اندروید: به متای viewport عبارت interactive-widget=resizes-content اضافه شود تا در Chrome اندروید هم dvh با کیبورد کوچک شود (iOS این را نادیده می‌گیرد و راهکار بخش ۳ کار را انجام می‌دهد).

۶. تست روی آیفون واقعی

  • مودال را باز کنید، روی «کد پیگیری» بزنید: دکمه باید بلافاصله بالای کیبورد دیده شود.
  • با کیبورد باز، بدنه‌ی مودال را اسکرول کنید: سربرگ و دکمه نباید تکان بخورند.
  • کیبورد را ببندید: مودال باید دوباره تمام‌صفحه شود و فاصله‌ی خالی پایینش نماند.
  • روی آیفون با Home Indicator (بدون دکمه‌ی خانه) و یک آیفون SE هم امتحان شود.
  • Enter کیبورد باید اطلاعات را ثبت کند.

این رفتار فقط روی Safari واقعی iOS دیده می‌شود؛ شبیه‌ساز مرورگر دسکتاپ کیبورد مجازی ندارد.
